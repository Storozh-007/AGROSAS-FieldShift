Платформа должна объединять:

1. Спутниковые наблюдения NASA.
2. Исторические климатические данные.

- Качество исходных данных.

Фермер должен задавать веса критериев:

- Сохранение воды.
- Здоровье почвы.
- Снижение рисков.
- Экономическая целесообразность.

# 6. НАСТОЯЩИЕ NASA-ИНТЕГРАЦИИ

## 6.1 NASA POWER — обязательный источник

Использовать официальный NASA POWER API.

Необходимо реализовать получение исторических климатических данных по координатам поля.

Минимальные параметры:

- T2M — температура воздуха.
- PRECTOTCORR — осадки.

Дополнительные параметры подключать только после проверки документации.

Реализовать:

- HTTP-клиент.
- Обработку ошибок.
- Таймауты.
- Повторные запросы.
- Кэширование.
- Проверку пропущенных значений.
- Сохранение исторических измерений.
- Привязку к полю.
- Отображение источника и периода.

## 6.2 NASA HLS — спутниковые изображения

Использовать Harmonized Landsat and Sentinel-2.

Цель — анализ растительности.

Реализовать получение и обработку доступных HLS-данных.

Основной показатель:

NDVI = (NIR - RED) / (NIR + RED)

Правильно выбирать соответствующие спектральные каналы HLS и учитывать масштабирование и маски качества.

Необходимо учитывать облачность, пропуски, геопривязку и временные интервалы.

В случае необходимости авторизации NASA Earthdata предусмотреть безопасную конфигурацию.

Если нет доступа к данным HLS, интерфейс должен показать честное состояние отсутствия данных и позволить выполнить демонстрацию на явно обозначенном тестовом наборе.

## 6.3 NASA SMAP

Предусмотреть подключение данных влажности почвы.

Учитывать различие пространственного разрешения SMAP и размера сельскохозяйственного поля.

Не создавать ложное впечатление, что SMAP непосредственно измеряет влажность каждого квадратного метра поля.

## 6.4 Дополнительные источники

Подготовить расширяемую архитектуру адаптеров для:

- GPM IMERG — осадки.
- ECOSTRESS — тепловые условия и эвапотранспирация.
- GLDAS — модельный водный баланс.
- NASADEM — рельеф.
- NISAR — доступные радиолокационные данные.
- NASA GIBS — картографические слои.

Не пытаться реализовать все источники одновременно.

Главный приоритет — работающий NASA POWER, затем HLS.

Для каждого источника сохранять:

- Имя набора данных.
- Идентификатор продукта, если есть.
- Период наблюдений.
- Пространственное разрешение.
- Дату загрузки.
- Статус качества.
- Признак наблюдения, модельного расчёта или демонстрационных данных.

Проверять официальную документацию и лицензии перед интеграцией.

# 7. AI И НАУЧНЫЙ ANALYTICS ENGINE

Разделить AI на три уровня.

## Level 1 — Scientific Processing

Python обрабатывает наблюдения.

Рассчитывать:

- Средние климатические значения.
- Климатические аномалии.
- Сезонную изменчивость осадков.
- Количество жарких дней.
- Индикаторы засушливости.
- NDVI и его изменения.
- Доступные индикаторы влажности почвы.

## Level 2 — Rotation Decision Engine

На основании научных показателей и агрономических ограничений сравниваются севообороты.

Результат должен быть воспроизводимым.

Каждое значение оценки должно иметь определённую формулу, входные данные и описание ограничений.

Создать отдельный конфигурационный каталог культур.

Для каждой культуры предусмотреть:

- Тип культуры.
- Период выращивания.
- Приблизительные требования к воде.
- Агрономические ограничения.
- Семейство культуры.
- Роль в севообороте.
- Возможный вклад в почвенный покров.
- Совместимость с региональными условиями.

Не выдавать эвристический алгоритм за проверенную модель прогнозирования урожайности.

## Level 3 — Explainable AI

LLM переводит структурированные результаты на понятный язык.

AI должен ссылаться на конкретные факторы и источники данных.

Если результат ненадёжен — прямо сообщать об этом.

Предусмотреть возможность будущего подключения Prithvi-EO-2.0 для специализированных задач анализа изображений.

Не делать тяжёлую foundation model обязательным условием запуска MVP.
